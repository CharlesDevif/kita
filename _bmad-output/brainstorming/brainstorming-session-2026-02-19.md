# Brainstorming Session Results

**Facilitateur:** Charles
**Date:** 2026-02-19

## Session Overview

**Sujet:** Kita — assistant IA mobile universel avec agent IA intégré (API Claude/OpenAI), modulaire par plugins, avec packs pré-configurés pour l'accessibilité (aveugles, sourds, muets, autistes) mais aussi pour les utilisateurs lambda.

**Objectifs:**
- Générer des idées de plugins et fonctionnalités
- Explorer les cas d'usage par type de profil utilisateur
- Définir le périmètre du MVP
- Imaginer l'architecture modulaire et le système de packs

### Session Setup

- **Concept clé:** L'agent IA utilise les ressources du téléphone (caméra, micro, GPS, capteurs) pour répondre aux demandes vocales ou écrites
- **Architecture:** Système de plugins ajoutables + packs pré-installés selon les besoins
- **Approche:** MVP d'abord, extension progressive
- **Exemple initial:** Plugin de description de photos pour personnes aveugles

## Technique Selection

**Approche:** Techniques recommandées par l'IA
**Contexte d'analyse:** Innovation produit + design inclusif + architecture technique

**Techniques recommandées:**

- **Role Playing:** Se mettre dans la peau de chaque type d'utilisateur pour révéler des besoins cachés
- **Cross-Pollination:** Transférer des solutions d'autres industries vers des plugins Kita
- **Morphological Analysis:** Croiser systématiquement utilisateurs × ressources téléphone × capacités IA × contextes

**Raisonnement IA:** Séquence empathie → inspiration externe → couverture systématique pour maximiser à la fois la profondeur et l'étendue des idées générées.

### Concepts architecturaux transversaux

1. **Plugins interconnectés** — Les plugins communiquent entre eux (météo → styliste → agenda)
2. **Multi-appareils** — Téléphone + lunettes connectées + montre + domotique
3. **Universalité** — Chaque plugin handicap a une version utile pour tout le monde
4. **Mémoire comme socle** — Le moteur de mémoire (#33-37) est la fondation de tout
5. **Escalade progressive** — Pattern réutilisable : script → médiation → régulation → SOS
6. **Architecture hybride** — On-device pour le temps réel/sécurité, cloud pour l'intelligence

### Priorité : Coeur technique MVP

**Architecture en 5 couches :**

```
COUCHE 5 : PLUGINS (les 100 plugins se branchent ici)
COUCHE 4 : INTERFACE (HUD adaptatif + communication adaptative)
COUCHE 3 : MÉMOIRE (structurée + indexée + chiffrée)
COUCHE 2 : CAPTEURS & I/O (STT + TTS + Caméra + GPS)
COUCHE 1 : AGENT IA (API Claude/OpenAI + orchestrateur + routeur de plugins)
```

**Architecture hybride cloud/on-device :**

- **On-device (latence <50ms) :** STT, TTS, détection d'obstacles, reconnaissance de sons, gestes
- **Cloud (200ms-2s) :** Analyse d'image complexe, raisonnement avancé, génération de texte, traduction

**Techno recommandée :** Flutter + modules natifs Swift/Kotlin pour les parties critiques (performance maximale)
