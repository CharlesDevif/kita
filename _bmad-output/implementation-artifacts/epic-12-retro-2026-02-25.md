## What Went Well

### 1. Architecture agent extensible
L'interface `KitaAgent` est propre et conforme au principe Open/Closed :
- Abstract class (pas sealed) — tout agent peut l'implémenter
- 5 méthodes de lifecycle claires + `onBusMessage` optionnel
- `buildViewport` optionnel pour agents sans UI
- `AgentManifest` déclaratif avec capabilities/permissions en strings libres

### 2. AgentBus découplé
- Subscribe sélectif par type de message
- Payload `Map<String, dynamic>` flexible
- Stream-based delivery — pas de polling
- Agents isolés — ne connaissent pas les autres

### 3. Migration plugins → agents sans régression
- DescribePlugin et AlertPlugin migrent vers KitaAgent
- Tous les tests existants continuent de passer
- OutputHandle remplace les appels directs aux services TTS/haptic

### 4. OutputCoordinator avec priorités
- 5 niveaux de priorité (CANCEL/CRITICAL/HIGH/STANDARD/LOW)
- Cooldown intelligent avec bypass sur approche rapide
- Deduplication temporelle
- Presence haptic post-interruption

### 5. Zero régression
- 1163 tests passent après la Phase 3.5
- `dart analyze` clean
- Les integration gates Phase 3 continuent de passer

## Challenges & Améliorations

### 1. Dev Agent Record non rempli (récurrent)
**Constat :** 1/4 stories ont le Dev Agent Record rempli (12.2 seulement).
**Phase 2 :** 1/28 stories avaient le record — même pattern.
**Cause racine :** Le workflow ne bloque pas le passage à `review` si le record est vide. C'est un processus humain, pas un gate automatique.
**Action :** Ajouter une vérification dans le workflow dev-story.

### 2. Code review en batch (récurrent)
**Constat :** Les 4 stories ont été review en un seul batch → 38 issues trouvées d'un coup.
**Phase 2 :** Même pattern (35 issues en batch).
**Impact :** Les corrections en cascade (signature OutputHandle.speak → 6 fichiers tests, ConsumerStatefulWidget → 2 gates) auraient été détectées plus tôt avec une review par story.
**Action :** Review après chaque story en Phase 4.

### 3. Corrections en cascade
- Changement de signature `OutputHandle.speak` (ajout `distance`, `cooldownKey`) → propagation dans 6 fichiers de test
- Migration `ConsumerStatefulWidget` → impact sur 2 integration gates
- `FakeClock` — bugs de fondation découverts tard (advance() ne fire pas les timers)

### 4. Story files non mis à jour
- 3/4 story files restent en `ready-for-dev` au lieu de `done`
- Seul 12.2 est passé à `review`
- Cela indique que les agents ne mettent pas systématiquement à jour le statut

### 5. Memory leak potentiel dans OutputCoordinator
- Les Maps `_cooldowns` et `_recentTexts` ne sont nettoyées que manuellement
- Pas de TTL automatique — en utilisation longue, les maps grandissent

## Notes de clôture

L'Epic 12 pose la fondation agent du projet Kita. L'architecture `KitaAgent`/`AgentBus`/`AgentSupervisor`/`OutputCoordinator`/`InputRouter` est propre, testée, et extensible. Les limitations identifiées (InputRouter monolithique, OutputCoordinator rigide) sont des choix MVP conscients, documentés, et réouvrables sans réécriture.

La principale dette process reste le non-respect systématique du Dev Agent Record et du code review par story. Ces deux points nécessitent des gates automatiques, pas de la discipline manuelle.

La Phase 4 (Onboarding + Background Services) peut démarrer. Le risque principal est le code natif iOS/Android (stories 10.1/10.2), qui nécessite une recherche technique approfondie lors du create-story.
