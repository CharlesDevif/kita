## Challenges

### Traçabilité des décisions
- **7/8 Dev Agent Records vides** — Stories 1.1-1.7 n'ont pas de trace des décisions prises, workarounds appliqués, ou problèmes rencontrés pendant l'implémentation
- **Cause systémique** : les stories n'ont pas été implémentées via le workflow BMAD `/bmad-bmm-dev-story` qui remplit automatiquement le record
- **Impact** : perte d'intelligence pour les agents Phase 2 qui auraient pu bénéficier de ces retours d'expérience

### Développement "en aveugle"
- **Impossible de builder/tester sur device** — toute la confiance repose sur les tests automatisés
- **Tests sur placeholders** — les 167 tests vérifient que les routes existent et que les widgets se rendent, mais les vrais comportements (caméra, TTS, STT, haptique) ne sont pas testés
- **Le vrai test de la fondation** sera la Phase 2 quand les agents brancheront les vrais services derrière les interfaces

### Pièges de dépendances
- 3 incidents de dépendances découverts en cours de route :
  1. `custom_lint` abandonné (bloqué analyzer 8)
  2. `sqlcipher_flutter_libs` 0.7.0+ deprecated
  3. `.env.example` capturé par le pattern `.gitignore` `*.env.*`
- Chaque piège aurait pu bloquer un agent Phase 2 s'il n'avait pas été documenté

---

## Key Insights

1. **Les tests doivent tester des comportements réels** — les mocks sur abstractions ne suffisent pas, surtout sans possibilité de build sur device
2. **Le Dev Agent Record est critique pour la traçabilité** — sans lui, on perd le "pourquoi" des décisions techniques
3. **CLAUDE.md est le contrat entre le projet et les agents** — il doit porter le workflow d'implémentation complet comme safety net du workflow BMAD
4. **L'architecture feature-first est la clé du parallélisme** — chaque agent possède son dossier, pas de conflit si la propriété des fichiers est respectée
5. **La code review est indispensable, pas optionnelle** — seul filet de sécurité pour certains bugs quand on ne peut pas tester manuellement
