Utilisé dans 9.3 (PermissionRequester), 9.4 (DescribeCallback, PersistProfileCallback), 10.3 (BatteryLevelProvider, LowBatteryAlertCallback). Découple le code, facilite les tests, permet le rewiring futur.

### 2. Zero PII dans les logs

### 3. Riverpod 3.0 patterns corrects
Toutes les stories utilisent `Notifier`/`AsyncNotifier`, aucun `StateProvider` deprecated. Leçon Phase 2 bien intégrée.

### 4. Accessibilité intégrée dès le départ
Semantics wrappers, contrastes, touch targets vérifiés sur chaque story UI. Pas de dette d'accessibilité.

### 5. Code review adversariale efficace
Les 4 CRITICAL trouvés étaient des vrais problèmes de câblage (permission jamais appelée à l'OS, TTS dans build() sans guard, processing guard inefficace, Future non-awaited). La review a prouvé sa valeur.

## Difficultés

### 1. `testWidgets` + StreamProvider = hang systématique
Touche 3/9 stories (9.1, 9.2, 10.4). Le test framework Flutter ne gère pas bien les `StreamProvider` actifs dans `testWidgets`. Solution à chaque fois : convertir en `test()` plain avec `ProviderContainer` + `try/finally dispose()`.

**Action :** Documenter dans CLAUDE.md.

### 2. Problèmes de câblage non détectés par les tests unitaires
Les 4 CRITICAL de la code review étaient tous des cas où le code compilait, les tests passaient avec des mocks, mais le comportement réel était cassé :
- `permission_step.dart` : bouton "Accepter" n'appelait jamais l'OS
- `caregiver_flow.dart` : TTS appelé à chaque `build()` sans guard
- `adaptive_sensor_controller.dart` : flag `_processing` reset immédiatement
- `passive_mode_impl.dart` : `adaptToMotion()` non-awaited dans callback sync

**Leçon :** La review adversariale est indispensable pour attraper le câblage manquant.

### 3. Fichiers protégés — blocage temporaire
Story 9.2 bloquée sur le câblage de `router.dart` (fichier protégé du leader). Résolu par modification directe du leader.

### 4. Différences plateforme iOS/Android
Camera impossible en background iOS (hardware-locked). Stories 10.1/10.2 ont nécessité des approches natives très différentes (ForegroundService vs AVAudioSession+CLLocationManager).
