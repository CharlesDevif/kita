### 1. Fichier protégé = blocage silencieux (RÉCURRENT)
Story 11.2 bloquée sur `pubspec.yaml` (ajout `integration_test: sdk: flutter`). Même pattern que Story 9.2 (Phase 4) avec `router.dart`. L'agent envoie un message au leader mais le blocage persiste sans résolution.

Engagement de la retro Phase 4 non respecté. Les 3 stories sont passées de `review` à `done` sans passage par `kita-reviewer`. Lancée pendant la rétro — 27 findings découverts dont 6 CRITICAL.

4 CRITICAL sur Story 11.2 : tests qui passent mais ne vérifient pas ce que les ACs exigent. Pattern classique "faux positif" :
- `populateDatabase()` ne pré-peuplait pas préférences, personnes, plugin data

- OrbState transition vers alert jamais asserté
- TTS output jamais vérifié dans describe journey

Les 3 stories avaient toutes les `[ ]` non cochées malgré le travail terminé. Signal que le workflow RED→GREEN→REFACTOR n'est pas suivi task par task.

Bug Ruby : `Regexp.last_match` écrasé par des `.match()` subséquents. La lane aurait crashé à la première utilisation. Détecté uniquement par la review adversariale.

## Insight clé : Confiance humaine dans le code IA

**Citation Charles :** "J'ai pas lu le code, j'ai laissé faire l'IA sans vérifier. Comment être sûr que tout est bon ?"

C'est la réalité des projets AI-first. Stratégie de validation recommandée :

| Couche | Automatisable | Confiance |
|--------|--------------|-----------|
| `dart analyze --fatal-infos` | ✅ | Bonne — erreurs types, lint |
| `flutter test` (1439 tests) | ✅ | Moyenne — la review a montré des faux positifs |
| Review adversariale (`kita-reviewer`) | ✅ | **Haute** — trouve ce que les tests ratent |
| Test on-device réel | ❌ Manuel | Critique — jamais fait |
| Review humaine sélective | ❌ Manuel | Complémentaire |
| Beta fermée avec vrais utilisateurs | ❌ Manuel | Ultime validation |

**Recommandation :** Pipeline automatisé (analyze + test + review adversariale) + test on-device + beta fermée 2-3 testeurs malvoyants.

## Leçons clés

1. **La review adversariale est le filet de sécurité le plus efficace** — 6 CRITICAL trouvés dont une lane cassée et des tests faux-positifs. Sans review, ces bugs seraient allés en beta.

2. **Les actions sans gate automatique ne tiennent pas** — 3 retros consécutives avec le même constat. Seules les règles encodées dans le CLAUDE.md ou le pipeline sont respectées.

3. **Le Dev Agent Record à 100% prouve que les gates dans CLAUDE.md fonctionnent** — Le taux est passé de 4% à 100% en 4 phases grâce à la documentation explicite du gate bloquant.

4. **La vitesse IA masque les angles morts** — 3 stories en 1 jour = pas le temps de review humaine. La stratégie doit être : générer vite, valider en profondeur (review adversariale + test on-device).

5. **La confiance humaine dans le code IA est un défi de process, pas de technologie** — La solution n'est pas de lire tout le code, mais d'avoir des couches de validation automatisées et ciblées.
